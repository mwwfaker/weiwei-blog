# `src/stores/` — 状态层（Pinia）

所有跨页面、跨组件的状态都在这里。页面组件**不持有业务状态**，只读 store、调用 store 的动作。

## 分工

| store | 管什么 | 关键约束 |
| --- | --- | --- |
| `auth.js` | 会话、token、当前用户 | 会话由 Supabase 自己持久化，刷新后要等 `restoreSession()` 才知道登录没登录。在那之前 `isLoggedIn` 一律是 `false`，**不能拿它判断「访客」**。 |
| `profile.js` | 昵称 / 简介 / 头像、站点可见范围、日记默认可见范围 | 前三项以账号库为准，同时镜像到 localStorage；后两项只是本机偏好，不落库。 |
| `articles.js` | 文章列表 + 筛选 + 搜索 + 编辑弹窗草稿 | 每条带 `mine`，别人的公开文章不能编辑。 |
| `diaries.js` | 我的日记 / 公开日记两份列表、导入草稿 | 页面内的「我的 / 公开」标签状态也在这里，因为它由路由 watch 设置。 |
| `media.js` | 图片与音频的元数据、两级相册（相册 / 子相册）、相册筛选、照片编辑草稿 | 音频的**播放**不在这里；「本地草稿 vs 真实记录」必须靠 `isStoredMedia()` 区分；相册 id 一律按字符串比。 |
| `music.js` | 播放、歌词、上传队列、可视化 | 两个 `<audio>` 的引用由 `modules/music/AudioEngine.vue` 交进来。 |
| `guestbook.js` | 留言板与友链 | 目前只存本机，提示语写的是「已添加到预览」，不假装已入库。 |
| `library.js` | **不持有状态**，只编排「按当前身份重读一遍」 | 登录成功 / 退出 / 首屏三处共用，避免再出现「退出了还能看到自己私密内容」。 |

## 三条约定

1. **读的策略统一是「公开的那份 + 自己账号里的那份」。** 公开列表（`/api/public/*`）对所有人完全一致，
   登录不会改变别人看到的东西，只是在同一份公开内容上再叠一层自己账号里的私密内容。
2. **归属靠 `mine` 标记，不靠「列表是从哪个接口来的」。** 公开列表里也有别人的内容。
3. **跨店调用只允许一个方向。** 现在的依赖是
   `library → {articles, diaries, media, music, profile}`、`music → media`、`articles/diaries → media/profile`、`profile → media`，
   没有回边。加新 store 时保持这个方向，否则会出现循环 import。

## 单例状态放在哪

`notify()`（提示）和 `currentPage`（当前页）**不在这里**，在 `src/app/` 的模块级单例里。
原因：它们要在任何组件挂载之前就能用，而且被 store 和组件同时调用。

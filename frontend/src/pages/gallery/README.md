## 版面为什么分两层

原来是一排筛选胶囊：只能筛照片，建不了空相册，也写不下「这盒里都是些什么」。
现在首页看的是**相册本身**——一盒一盒摆着，每盒有封面、名字、张数、描述；
点开某盒才进入照片网格。

首页的顺序是固定的：**盒子在前，散落在外的照片在后**（那批照片有小节标题，
副标题写「N 张 · 还没放进盒子」）。**没有「未分类」这个盒子**：没归进盒子的照片就散落在外面。

盒子的三个状态都有交代：

| 情况 | 看到什么 |
| --- | --- |
| 盒子里有照片 | 最多 4 张拼贴成封面 |
| **空盒子** | 虚线 + 淡符号的默认样式（它只是还没装东西，不是不存在） |
| 一级相册，照片都在子相册里 | 小一号的子盒子摆一排 + 一句「这本相册自己的照片还空着」 |

> **空盒子只有你自己看得到。** 访客走的是 `/api/public/photo-albums`，它只返回
> "装着公开照片"的相册（RLS 也只放行这些）—— 空相册的名字不该漏给访客。

## 整理照片：移动与多选

整理是一批一批挪的，所以除了每张照片下面的「移动」，还有一层**多选**：

1. 照片区右上角「选择照片」→ 照片上出现勾选圈
2. 勾若干张 → 「移到相册」→ 在列表里挑一本（或「不放进盒子」）→ 移动
3. 完成后自动退出多选

一次只挪到一本相册（不是多选目标）：这是"整理"的动作，不是"批量打标签"。
挪到「不放进盒子」的照片会回到首页散落区。

## 照片的日期用「拍摄时间」

网格与看图里显示的月份优先用 **EXIF 的拍摄时间**（`takenAt`），没有才回退到上传时间。
用上传时间会让相册的时间排序莫名其妙，也会让「X 年前的今天」变成「你哪天传的」。

首页那张**回忆卡**（「N 年前的今天」）就是按 `takenAt` 的月日匹配今天算出来的，
只在真有匹配时才渲染 —— 所以它一出现就是个惊喜。计算在客户端做（照片本来就在内存里）。

## 网格加载的是缩略图

上传时在本机生成一张 640px 的 WebP（约 30 KB）另存一份，网格与相册封面用它；
**全屏看图仍然用原图**。没有缩略图的老照片会自动回退到原图，所以这张新表不会让老数据变坏。

## 上传流程

**「添加照片」一次可以选多张**（`<input multiple>`）。选完不会立刻开传，而是先弹上传对话框：

1. 上面选**放进哪一本**（默认 = 你现在打开的那本；停在首页时默认「先散落在外面」）、
   写一条**统一描述**、选可见范围；
2. 下面一张张核对名称与描述（某张单独写了就用它的，留空就用统一描述），不要的可以删掉；
3. 点「开始上传」→ 逐张传，页脚显示 `正在上传 n / N` → **全部成功才关窗**。

浏览器 → 对象存储是**直传**：`POST /api/storage/presign-upload` 拿签名 → 传文件 →
`POST /api/media` 存元数据（名称 / 描述 / 归属 / 可见范围）。服务端不转发文件本体。

未登录时点「添加照片」会被 `requireLogin()` 挡下并带到账号页。

**照片默认进哪一盒，看的是「你现在正开着哪一盒」**：打开某本相册（或它的子相册）时，
对话框的默认去处就是那一本；停在首页时默认「先散落在外面」。少了这条，
每张上传完都得再手动归一次。

## 三种照片混在一个列表里

内置示例、未登录时在本机加的照片（`data:` 地址、没有对象键）、服务器上的真实记录。
只有第三种能按 id 调接口，判断走 `media.isStoredMedia(item)`。

## 相册是两级的（相册 → 子相册）

相册是**真表**（`photo_albums`），不再是照片上的一个名字：

- 照片的归属是 `albumId`，`albumName` 只是给公开照片墙显示用的副本（原因见 `services/api.js`）。
- 删掉一本相册时里面的照片会回到**散落在外**，**照片不会被删**。
- 两级是数据库触发器强制的（`photo_albums_keep_two_levels`）：子相册下面不能再建子相册，
  有子相册的相册也不能再挂到别人下面。
- **打开一级相册时看到的是它直辖的照片**，子相册的照片在子盒子里（点进去看）。
  盒子上那个数字则是含子相册的总数。
- 访客只看到「装着公开照片」的相册，而且不能编辑。一级相册自己没有公开照片时，
  它的子相册会被当成一级显示——否则那本子相册会整个消失。
- 名字与描述一起在「编辑相册」里改（`AlbumEditorDialog`）。描述允许留空。

## 全屏看图里还有两件事

- **ⓘ 照片信息**：拍摄参数（EXIF，只取图片前 256 KB）+ 这张照片的主色（点色块复制色值）。
  两者都可能没有 —— 截图、微信/微博保存的图、Unsplash 之类都会抹掉元数据，这时显示一句「没有」。
- **✦ 立体浏览**：把照片按深度摊成点云、可拖动换视角。它是**浮雕/视差级的 2.5D**，
  不是能走进去的真实 3D；模型 18–26 MB，首次点要下（之后缓存）。细节见
  `modules/media/README.md` 的「立体浏览」一节（那里记着两个必须记住的坑）。

## 电影感播放

首页的「▶ 电影感播放」放**全部照片**（当站点放映），相册里的「▶ 播放」放这一盒的。
每张停留 5 秒、淡入 1.4 秒；空格暂停、← → 翻页、Esc 退出。

首页刻意放"全部"而不是只放散落的那几张 —— 只放散落的，几张就播完了，不像放映。

## 全屏看图的关闭

关闭走的是阅读弹窗那套「先定住一拍、再化作尘埃」的动效，时序在
`composables/useDustClose.js`（和 `ReadingSheet` 共用同一份）。粒子铺在**图片原来的位置**上。

因此 **`AppShell` 里不能再给它包 `<Transition>`**：外层一包，`v-if` 会在动画开始前
就把组件摘掉，粒子一个都来不及飞。

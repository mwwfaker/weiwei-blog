# 相册（生活切片）

路由 `/gallery`。**两层版面**：首页摆一盒一盒相册，点开某盒才看里面的照片。

## 文件

| 文件 | 位置 | 内容 |
| --- | --- | --- |
| `GalleryPage.vue` | 这里 | 标题区、「添加照片」、盒子首页 / 盒子内部的切换 |
| `AlbumBoxes.vue` | `modules/media/` | 相册盒子（封面拼贴 + 名字 + 张数 + 描述） |
| `GalleryGrid.vue` | `modules/media/` | 盒子里的照片网格与每张下面的操作行 |

| `MediaEditorDialog.vue` | `modules/media/` | 照片信息编辑：名称 / 描述 / 所属相册 / 可见范围（外壳挂载） |
| `AlbumEditorDialog.vue` | `modules/media/` | 编辑一本相册的名字与描述（外壳挂载） |

## 版面为什么分两层

原来是一排筛选胶囊：只能筛照片，建不了空相册，也写不下「这盒里都是些什么」。
现在首页看的是**相册本身**——一盒一盒摆着，每盒有封面、名字、张数、描述；
点开某盒才进入照片网格。截图里那本「文章封面」就是老照片上的相册名被自动升级成的真相册。

盒子的三个状态都有交代：

| 情况 | 看到什么 |
| --- | --- |
| 盒子里有照片 | 最多 4 张拼贴成封面 |
| **空盒子** | 虚线 + 淡符号的默认样式（它只是还没装东西，不是不存在） |
| 一级相册，照片都在子相册里 | 小一号的子盒子摆一排 + 一句「这本相册自己的照片还空着」 |

## 上传流程

浏览器 → 对象存储是**直传**：`POST /api/storage/presign-upload` 拿签名 → 传文件 →
`POST /api/media` 存元数据。Java 服务不转发文件本体。

未登录时点「添加照片」会被 `requireLogin()` 挡下并带到账号页。

**照片进哪一盒，看的是「你现在正开着哪一盒」**：打开某本相册（或它的子相册）时上传，
照片直接进那一本；停在首页 / 全部照片 / 未分类时不归相册。少了这条，每张上传完都得再手动归一次。

## 三种照片混在一个列表里

内置示例、未登录时在本机加的照片（`data:` 地址、没有对象键）、服务器上的真实记录。
只有第三种能按 id 调接口，判断走 `media.isStoredMedia(item)`。

## 相册是两级的（相册 → 子相册）

相册是**真表**（`photo_albums`），不再是照片上的一个名字：

- 照片的归属是 `albumId`，`albumName` 只是给公开照片墙显示用的副本（原因见 `services/api.js`）。
- 「未分类」= `albumId` 为空。删掉一本相册时里面的照片会回到这里，**照片不会被删**。
- 两级是数据库触发器强制的（`photo_albums_keep_two_levels`）：子相册下面不能再建子相册，
  有子相册的相册也不能再挂到别人下面。
- **打开一级相册时看到的是它直辖的照片**，子相册的照片在子盒子里（点进去看）。
  盒子上那个数字则是含子相册的总数。
- 访客只看到「装着公开照片」的相册（RLS 与 `/api/public/photo-albums` 都按这条过滤），
  而且不能编辑。一级相册自己没有公开照片时，它的子相册会被当成一级显示——否则那本子相册会整个消失。
- 名字与描述一起在「编辑相册」里改（`AlbumEditorDialog`）。描述允许留空。

## 全屏看图的关闭

关闭走的是阅读弹窗那套「先定住一拍、再化作尘埃」的动效，时序在
`composables/useDustClose.js`（和 `ReadingSheet` 共用同一份）。粒子铺在**图片原来的位置**上。

因此 **`AppShell` 里不能再给它包 `<Transition>`**：外层一包，`v-if` 会在动画开始前
就把组件摘掉，粒子一个都来不及飞。

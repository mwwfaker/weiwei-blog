# `pages/study/data/` — 学习计划的数据

| 文件 | 内容 |
| --- | --- |
| `studyPlan.js` | 金融学那份计划的结构化数据（29 门课 / 5 个阶段 / 资源链接） |
| `studyPlans.js` | **计划库**：一份数组，页面从它读；加新学习计划就是往这里加一项 |

## 加一份新计划的两种方式

### A. 直接加数据文件（现在就能用）

复制一份 `studyPlan.js` 改成新计划，然后在 `studyPlans.js` 里加一项：

```js
{
  id: 'ielts',                 // 唯一，用来分开存进度
  name: '雅思 7.5 备考路线',
  short: '雅思',                // 计划库那一行按钮上的字
  note: '一句话说明这份计划是什么',
  plan: ieltsPlan,
}
```

页面上的阶段标签**不是写死的**，是从课程的 `stage` 字段里长出来的，所以新计划可以有
完全不同的阶段名和数量。进度按 `id` 分开存（`weiwei-blog-study-progress:<id>`），互不干扰。

### B. 从 Word 导入（建议下一个做）

大多数计划是 AI 写好后给一份 Word。要可靠地变成本目录的结构，需要**固定模板**：

1. `# 计划名`（一级标题）
2. `> 一句话说明`（引用块）
3. 每个阶段：`## 阶段名` + 一段目标描述
4. 每门课：`### 课程名`，下面用列表写：重要性（1–5）、预计时长、前置课程、核心概念、完成标准、练习
5. 资源用普通列表：`- [标题](链接)`

导入流程建议：选文件 → mammoth 解析成 HTML/文本 → 按标题层级映射成 plan 结构 →
**先预览再保存**（和文章/日记导入一样，不要直接写库）。解析器放 `services/studyImport.js`，
保持纯函数，方便像 `verify-article-import` 那样离线对拍。

**更稳的替代方案**：让 AI 直接输出 JSON（给它一份 schema + 一段 prompt），存成 `.json` / `.txt`
再导入。Word 的表格、合并单元格、目录会让解析器很脆；JSON 没有这些问题。

## 约定

- **这是内容，不是代码。** 课程名、阶段、资源链接都是「站主写下的东西」。
- **不要在前端改写内容。** 要改课程就改数据文件（或重新生成），不要在 `StudyPage.vue` 里做字符串处理。
- 体量约 300 kB，所以学习页是按需加载的（见 `src/app/pageRegistry.js`）。

# frontend/src/styles 结构说明

`index.css` 只做 `@import`，不放任何规则。**import 顺序 = 层叠顺序**（后面的覆盖前面的），
顺序与原 `app.css` 的行区间一一对应，禁止重排、禁止把两个文件并成一个。

这次重构只做了一件事：把原 `app.css` 按**连续行区间**原样切开。所有文件首尾相接拼起来，
与原文件逐字节相同（SHA256 一致），构建产物大小也完全相同，因此页面渲染没有变化。

## 为什么必须是这个顺序

原 `app.css` 不是按职责组织的，而是按**开发与修复轮次**一层层追加的：先首版布局，再补黑夜主题，
再做 2026 编辑风改版，再叠加视觉动效升级层与第二轮修复，最后追加音乐、歌词/导入队列、
以及整体放柔和白天主题补写。后面的轮次不断覆盖前面的同选择器声明（同一个 `.nav-item`、
`.article-card` 在多个文件里出现），所以顺序本身就是语义，不能按「看起来该放哪」重排。

## 新增样式该放哪

- 主题变量、深夜色覆盖 → `dark-theme.css`
- 通用重置、字体、栅格、断点 → `base.css`
- 动效、过渡、玻璃质感、弹层动画 → `effects-and-fixes.css`
- 播放器、唱片、音乐盒 → `music.css`
- 歌词栏、导入队列、任务卡 → `lyrics-and-import.css`（日记导入确认弹窗也在这里，
  见文件末尾那一节：它的选择器带 `.import-card` 前缀，是为了压过 `.modal-card input`
  这类多一个元素选择器的规则）
- 浅色（白天）主题补写、收尾微调 → `polish-and-light-theme.css`（**阅读弹窗的版面与字号行距
  也在这一节**，见文件末尾「阅读：表头固定，只有正文滚动」——放这里是因为它必须压过
  `base.css` 的 `.modal-card{overflow:auto}` 和 `editorial-2026.css` 的 `.article-reading`）

放进已有文件时**追加到该文件末尾**；不要插到文件中间，也不要新建一个页面文件塞进 import 列表中间——
那会改变层叠顺序。确实要新增文件时，只能接在列表末尾。

## 例外：页面自己的样式表

`styles/` 装的是**全站共用**的样式。如果某个页面是按需加载的，它那份样式可以（也应该）放在页面文件夹里、
由页面组件自己 `import './xxx.css'`——这样样式跟着异步 chunk 走，不进首屏包。

现在的例子是 `pages/perf/perf.css`（绩效计算器，约 36 kB）。它**故意不出现在本目录的 import 列表里**。
`verify-frontend.mjs` 会顺着组件里的 `import '*.css'` 一起找，所以检查不会漏。
代价是这份样式不参与本目录的层叠顺序——所以它只允许作用于那个页面自己的根类（例如 `.perf-tool`）。

# frontend/src/styles 结构说明

`index.css` 只做 `@import`，不放任何规则。**import 顺序 = 层叠顺序**（后面的覆盖前面的），
禁止重排、禁止把两个文件并成一个。

## 为什么顺序本身就是语义

这套样式不是按职责组织的，而是按**开发与修复轮次**一层层追加的：先首版布局，再补黑夜主题，
再做 2026 编辑风改版，再叠加视觉动效层与第二轮修复，然后追加音乐、歌词/导入、整体放柔与白天主题，
最后是 2026 换壳（`shell-2026` / `home-stage` / `home-day`）与日记时间树。
后面的轮次不断覆盖前面的同选择器声明（同一个 `.nav-item`、`.article-card` 在多个文件里出现），
所以**顺序不能按「看起来该放哪」重排**。

## 文件一览

| 顺序 | 文件 | 装什么 |
|------|------|--------|

| 4 | `effects-and-fixes.css` | 视觉与动效升级层（极光、滚动揭示、文字流光、玻璃质感、按钮、弹层、滚动条、无障碍）＋第二轮修复（粒子可见性、横向溢出、标题被裁、主题固定色、导航下滑收起） |
| 5 | `music.css` | 音乐板块：播放器/歌词控制台、唱片与涟漪、曲目行、右下角悬浮音乐盒的两种形态与窄屏抬升 |
| 6 | `lyrics-and-import.css` | 歌词栏（滚动、居中、高亮、骨架屏）、曲库里的歌词状态、后台导入任务卡与音乐页内联导入队列 |
| 7 | `polish-and-light-theme.css` | 「整体放柔」（位移/时长/模糊收敛）、统一圆角、响应式收尾、白天主题补写、**阅读弹窗的版面与字号行距** |
| 8 | `diary-tree.css` | 日记「时间树」：树干、挂在轴上的卡片、年份牌子、按侧展开的入场、增删日记时的高度折叠。**必须排在 `polish-and-light-theme.css` 之后**：它要压过那里的 `.reveal{translate:0 16px}`（纵向揭示），而 `.reveal.is-visible{translate:none}` 与 `.diary-tree-node.reveal{translate:…}` 同为 (0,2,0)，只能靠排后面赢 |

| 10 | `shell-2026.css` | 全站换壳：悬浮顶栏、底部胶囊 dock 与「更多」面板、页面液态转场、通栏容器、全站公共表面（内页标题、卡片、按钮、工具条、分类胶囊）。要压过 base / editorial / polish 的旧壳规则。**学习库、编织页、工具页的版面也在这里** |
| 11 | `home-day.css` | 白天主题的第二套首页（纸艺立体书）：整页是一本摊开的书，中缝书脊、页码、纸颗粒、会站起来的纸艺立体页。夜里仍是 `home-stage.css` 的星空世界，两套版面互不覆盖 |

## 新增样式该放哪

- 主题变量、深夜色覆盖 → `dark-theme.css`
- 通用重置、字体、栅格、断点 → `base.css`
- 动效、过渡、玻璃质感、弹层动画 → `effects-and-fixes.css`
- 播放器、唱片、音乐盒 → `music.css`
- 歌词栏、导入队列、任务卡 → `lyrics-and-import.css`（日记导入确认弹窗也在这里：选择器带 `.import-card`
  前缀，是为了压过 `.modal-card input` 这类多一个元素选择器的规则）
- 白天主题补写、收尾微调、阅读弹窗版面 → `polish-and-light-theme.css`（阅读那一节放这里，
  是因为它必须压过 `base.css` 的 `.modal-card{overflow:auto}` 与 `editorial-2026.css` 的 `.article-reading`）
- 全站外壳与公共表面、学习/编织/工具页的版面 → `shell-2026.css`
- 首页 → 夜 `home-stage.css` / 昼 `home-day.css`

放进已有文件时**追加到该文件末尾**；不要插到中间，也不要新建文件塞进 import 列表中间——
那会改变层叠顺序。确实要新增文件时，只能接在列表末尾。

## 别让样式变成垃圾：类名必须有人用

**每一份样式表里的每个类名，模板里都必须真的用得上。** `verify-frontend.mjs` 的第 [13] 项
会反向检查这件事：一个类名如果在 `src/` 的所有 `.vue` / `.js` 里一次都不出现，它就报错。

这条规则是 2026 年补的，起因很具体：首页重做（`HeroCard` / `QuoteCard` / `DiaryPreview` 删除）、
侧边栏删除、4 个页面（归档/分类/标签/友链）下线、学习页改版 6 次——**每次组件删了都没有删样式**，
累积下来有 179 个类名没有任何模板在用，占全部样式的 25%（首屏 CSS 206 kB → 164 kB）。
删掉之后加上第 [13] 项，这类腐烂就不会再悄悄发生。

三个例外登记在脚本的 `KNOWN_UNUSED_CSS` 里，每一条都要写原因；对应的样式修好或删掉之后，
脚本会反过来提醒你把那一行删掉——**登记簿过期会报错**，所以它不会变成摆设。

## 例外：页面自己的样式表

`styles/` 装的是**全站共用**的样式。如果某个页面是按需加载的，它那份样式可以（也应该）放在页面文件夹里、
由页面组件自己 `import './xxx.css'`——这样样式跟着异步 chunk 走，不进首屏包。

现在的例子是 `pages/perf/perf.css`（绩效计算器）。它**故意不出现在本目录的 import 列表里**。
`verify-frontend.mjs` 会顺着组件里的 `import '*.css'` 一起找，所以检查不会漏。
代价是这份样式不参与本目录的层叠顺序——所以它只允许作用于那个页面自己的根类（例如 `.perf-tool`）。

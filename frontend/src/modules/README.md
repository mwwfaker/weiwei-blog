# `src/modules/` — 按领域成套的组件

每个文件夹是一个**领域**（music / diary / media / article / page / modal / profile / particle），
不是按「被几个页面用」分出来的。判断标准是：

> 这个组件属于哪个领域？如果它所在的页面被删掉，它还有别的地方能去吗？
> **有** → 放这里；**没有、而且它只是那一页版面上的一块**（工具条、统计块、面板）→
> 放 `src/pages/<页面>/components/`。

所以要区分的是「领域组件」和「页面版面部件」，**不是**「被几个页面用了」。
`modules/music/` 里既有一处挂载、全站可用的音乐盒，也有只服务音乐页的曲库面板——
它们都是「音乐」。

每个文件夹里的组件之间可以自由互相引用（例如 `ArticleGrid` 用 `ArticleCard`）。

## 子目录

| 目录 | 内容 | 谁在用 |
| --- | --- | --- |
| `page/` | 内页标题区、二级标题、页脚、空状态 | 几乎所有内页 |
| `modal/` | 弹窗外壳（背板 + 卡片 + 标题行 + 关闭按钮） | 九处弹窗全部 |
| `article/` | 文章卡片、网格、阅读弹窗、编辑弹窗 | 首页、文章页、外壳 |
| `diary/` | 日记卡片、编辑弹窗、阅读弹窗、导入确认弹窗 | 首页、日记页、外壳 |
| `media/` | 相册分类条、照片网格、全屏看图、照片信息编辑 | 相册页、外壳 |
| `music/` | 播放器面板、曲库、导入队列、音乐盒、歌词栏、频谱画布、音频元素 | 音乐页、外壳 |
| `profile/` | 个人资料弹窗 | 外壳（顶栏和侧边栏都从那里进入） |
| `particle/` | 首页背景粒子画布 | 外壳 |

## 约定

- **允许读 store。** 这些不是「纯展示组件库」，而是这个项目自己的复用块。文章卡片直接问
  `useArticlesStore()` 要封面地址，比让每个调用点都算一遍再往下传要短得多。
- **跨页共用的状态放在 store 里，不放在组件里。** 例如文章编辑弹窗的草稿在
  `stores/articles.js`，所以从首页打开和从文章页打开是同一份。
- **样式用全局类名，不写 `<style scoped>`。** 现有样式表按层叠顺序组织（见 `src/styles/README.md`），
  在组件里再写一份 scoped 样式会让同一个元素的规则散在两个地方。
- **`v-reveal` 要在组件里 import**（`import { vReveal } from '@/composables/motion'`），
  它是局部注册的指令，没有全局注册——渲染测试会单独挂载组件，那时没有全局指令可用。

## 一个新块该放哪

1. 只在一个页面里用 → `pages/<页面>/components/`。
2. 属于某个领域、或者外壳也要挂载 → 在 `modules/` 下按主题建目录（没有合适的就新建一个并在这里登记）。
3. 纯工具箱性质、和博客内容无关（按钮、输入框之类）→ 先别建，等到真的出现第三个调用点再说。

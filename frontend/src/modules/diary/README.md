# `modules/diary/` — 日记相关复用件

| 文件 | 用途 |
| --- | --- |
| `DiaryCard.vue` | 日记卡片。`showActions` 打开下面的操作行，`showVisibility` 在元信息里显示「◉ 公开 / ◌ 仅自己」。 |
| `DiaryEditorDialog.vue` | 写 / 改日记。可见范围默认值来自 `stores/profile.js`。 |
| `DiaryReaderDialog.vue` | 阅读弹窗。编辑按钮只在本人（或本机草稿）时出现。版面走 `modules/modal/ReadingSheet.vue`：日期/标题/标签与底部按钮固定，**只有正文滚动**。 |
| `DiaryImportDialog.vue` | 导入确认：先把文件解析成草稿让人核对，确认后才写库。一个文件里装很多篇会按日期拆开；顶端有「统一发布权限」，一次给所有草稿定公开/私密。写入期间按钮禁用并显示进度（见下）。 |

## 两个视图共用一张卡片

日记页有「我的日记」和「公开日记」两份列表，结构一致、只差一个操作行和一行元信息。
差异做成了两个布尔 prop，而不是两个组件——否则以后改一处排版要改两遍。

## 日期格式

日记的日期是 `2026-09-30`。卡片上显示成「30 / 2026 / 09」，归档页把它归一化成 `2026.09`
（文章的日期本来就是 `2026.09.18` 形态）。归一化在页面里做，卡片只管显示。

## 导入不丢内容

关闭确认弹窗不会丢掉已解析的草稿——它留在 `stores/diaries.js` 的 `importReview` 里，
重新打开还在。服务器拒绝的那几篇也会留在同一条列表里，方便重试而不是重读文件。

## 「整合日记」怎么拆成一篇篇

拆分规则在 `services/diaryImport.js`（纯函数，`verify:diary` 直接 import 它对拍），
**不在弹窗里**——规则错了只会表现成「多了几篇很长的、少了几篇」，而这直接写进数据库。

- 认的日期头：`2023 年 5 月 29 日 周一`、`2026年9月21日`、`2024-05-05`、`2024年11月28日。`
  （整行锚定，所以正文里提到日期不会被切开）。星期几不进标题，标题统一成 `2023年5月29日`。
- **也认「正文里自带日期」的篇**：`今天是2025年2月7号，也是农历正月初十。……` 这种没有独立
  日期行的日记，以前会被并进上一篇（真实文件里就漏过一篇：50 篇只拆出 49 个独立篇）。
  这一行本身留在正文里。一个文件一篇时它不会切成「空篇 + 真篇」，见 `matchInlineDiaryStart`。
- **结尾那行「时间 莫唯唯」原样留在正文里**，没有单独解析成字段：少一处格式假设，
  导出与阅读就还是当初写下的样子。
- 一行都不丢是硬要求：核对方式是「源文件非空行数 − 日期头行数 = 各篇正文行数之和」。
- 顶部不属于任何一篇的段落（例如文件总标题）会单独留一篇（`date` 为空，由 store 补今天），
  **宁多一篇让人删，也不悄悄吞掉**。

## 为什么「确认并保存」要防重复点击

一次点击会**并发发几十个请求**（实测 50 篇约 1 秒）。按钮在那期间不禁用的话，
手快的人点两下就是两份完全相同的内容——而且它们标题日期一模一样，事后只能配对删。

所以 `confirmImport` 里有两道：`importing` 为真时直接返回（不只是把按钮变灰），
以及按钮显示 `保存中 12 / 50` 让人知道它在跑。`importing` 在 `finally` 里复位——
不放 finally 的话，一次网络异常就会让按钮永久卡在「保存中」。

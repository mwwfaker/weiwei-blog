# `modules/media/` — 相册相关复用件

| 文件 | 用途 |
| --- | --- |
| `AlbumBoxes.vue` | 相册**盒子**：封面拼贴 + 名字 + 张数 + 描述 + 「相册」徽标。空盒子有默认样式。 |
| `GalleryGrid.vue` | 照片网格 + 多选工具条。每张下面的操作行只在「已登录 + 是自己的照片」时出现。 |
| `GalleryViewer.vue` | 全屏看图，点空白或右上角关闭；本人照片可以直接在这里删。关闭时化作尘埃。 |
| `MediaEditorDialog.vue` | 照片信息编辑：名称、描述、所属相册、可见范围。 |
| `PhotoMoveDialog.vue` | 「移到相册」：把一张或一批照片挪到别的盒子，或挪到盒子外面。 |
| `PhotoUploadDialog.vue` | 一次选多张：传之前先写名称/描述、挑去处与可见范围。 |
| `AlbumManagerDialog.vue` | 相册管理：新建一级相册 / 子相册、改名、删除。 |
| `AlbumEditorDialog.vue` | 编辑一本相册的名字与描述。 |
| `PhotoDepthViewer.vue` | 立体浏览：把照片按深度摊成点云，可拖动换视角。 |
| `PhotoInfoPanel.vue` | 照片信息：拍摄参数（EXIF）+ 这张的主色。 |
| `PhotoSlideshow.vue` | 电影感播放：缓慢推近 + 淡入淡出，键盘翻页。 |
| `depth.js` | 浏览器端深度估计（Depth Anything V2 small）。**不是组件**，被上面那个查看器调用。 |

## 立体浏览：说清楚它是什么

点「✦ 立体浏览」→ 用 Depth Anything V2 small 在**访客自己的电脑上**算出深度图 →
把照片摊成一团点云（三万来个点，每个点按深度前后错开），可以拖动换视角、滚轮缩放。

- **它是"浮雕/视差级"的 2.5D，不是能走进去的真实 3D 场景。** 后者需要生成式流水线
  （比如 image-blaster 那种：Claude 技能 + World Labs/FAL 付费 API），做不到"点一下就有"。
- **零服务器成本、照片不出本机**：模型跑在浏览器里（WASM 或 WebGPU）。代价是首次要下
  18–26 MB 模型（之后走浏览器缓存，**第二张照片是秒开**）。
- three.js 与模型都是**点进去才动态加载**的，平时翻相册不会多下一字节。

### 两个必须记住的坑（都实测踩过）

1. **必须关掉 onnxruntime-web 的多线程**（`numThreads = 1` + `proxy = false`）。
   线程版要 `SharedArrayBuffer`，站点没发 COOP/COEP 响应头时推理会**永远不返回、也不报错**，
   看起来像"模型太大跑不动"，实际是无声死锁。
2. **不能只看 `navigator.gpu` 是否存在来决定用不用 WebGPU。** 无头浏览器、老驱动、
   关了硬件加速的机器上它照样存在，但适配器拿不到；而一旦让 onnxruntime 去试 WebGPU 并失败，
   **整个运行时会留在坏状态**，之后连 WASM 都报 `no available backend found`（回退都救不回来）。
   所以先 `navigator.gpu.requestAdapter()` 探一次，拿不到就直接走 WASM。

模型默认从 HuggingFace 取。国内网络或想自托管时用构建变量换源（保持目录形状）：

```
VITE_DEPTH_MODEL_HOST=https://hf-mirror.com
VITE_DEPTH_MODEL_HOST=https://<项目>.supabase.co/storage/v1/object/public/weiwei-assets
```

## 照片信息与电影感播放

- `PhotoInfoPanel`：EXIF **只取图片前 256 KB**（EXIF 在头部，为一行参数下一整张不值当）；
  配色板把图画到 96×96 数一遍。两者失败都正常（社交平台会抹掉 EXIF、跨域图读不了像素），
  这时显示一句「没有可读的拍摄信息」，不报错。色块点一下复制十六进制。
- `PhotoSlideshow`：每张停留 5 秒、淡入 1.4 秒，推近动画 6 秒 —— **推近比停留略长**，
  切换时它还在走，不会有"停下来再切"的顿感。空格暂停、← → 翻页、Esc 退出。

## 上传：先填信息，再上传

`PhotoUploadDialog` 把顺序反过来了 —— **不是选完文件就立刻开传**，而是先排队：

- 上面一批**统一设置**：放进哪一本（默认就是你现在打开的那本）、统一描述、可见范围；
- 下面一张张核对：缩略图（`URL.createObjectURL` 的本机预览）+ 名称（默认取文件名）+ 自己的描述
  （**填了就用它，留空就用统一描述**），不要的可以单张删掉；
- 点「开始上传」后**逐张传**，页脚显示 `正在上传 n / N`；
- **全部成功才关窗**；有失败的会留在列表里方便重试。

为什么不是选完就传：一次选十张手机照片，全落进同一个相册、名字都是 `IMG_2031` 这种，
事后还得一张张回去改。逐张传而不是并发：几十条并发在免费额度上更容易被限流，进度也说不清。
object URL 在关窗/删条目时**必须 revoke**，否则一次选二十张手机照片会一直占着内存。

## 为什么是「盒子」而不是一排筛选胶囊

胶囊只能**筛**：看不见里面有什么，也放不下描述，更没法表达「这盒现在是空的、我打算以后往里放东西」。
盒子是**能先建好、先取名字、先写描述，再慢慢装照片**的东西，所以：

- **空盒子照样显示**，给一套虚线 + 淡符号的默认样式，而不是因为没照片就消失；
  （**访客例外**：`/api/public/photo-albums` 只返回"装着公开照片"的相册，所以空盒子只有你自己登录时才看得到）
- 封面是**最多 4 张的拼贴**（一级相册连子相册的照片一起算 —— 只拍子相册的那本不该显示成空盒）；
- 名字下面还有一行**相册描述**，用来写「这盒里都是些什么照片」。

## 盒子和照片必须一眼分得开

首页是「盒子在前、散落在外的照片在后」，相册内部是「子盒子一排、自己的照片一片」——
两种东西挨得很近，所以：

- 每个盒子左上角都有 **「相册」/「子相册」徽标**；
- 子相册额外用**虚线 + 淡底**（它和照片挨得最近，最容易混）；
- 照片卡片不带徽标、不带虚线。

改样式时别把这三条一致性弄丢：只靠间距和大小，扫一眼是分不出来的。

## 相册内部：照片和子盒子分开摆

打开一本一级相册时，**子相册以小一号的盒子单独摆一排**，下面才是这本相册**直辖**的照片
（`albumPhotos(id)` 只看 `albumId === id` 的）。两者不混在一起：
混了以后就分不清「这张到底在哪一层」，而「删掉子相册」的影响范围也会变得难以预料。

盒子上显示的数字是**含子相册的总数**（`albumTotal`），否则「旅行」显示 0 张、点进去却有照片。

## 没有「未分类」这个盒子

没归进盒子的照片就**散落在首页上正常展示**（`loosePhotos`）。刻意不做「未分类」盒子：
多一个盒子等于凭空多一层收纳，而它装的其实是「我还没想好放哪」的东西。
网格里这种照片的副标题写「散落在外」，不要凭空给它造一个分类名。

## 「本地草稿」和「真实记录」

`galleryItems` 里混着三种东西：内置示例、未登录时在本机加的照片（`data:` 地址、没有对象键）、
以及服务器上的真实记录。只有第三种能按 id 调接口。

判断走 `useMediaStore().isStoredMedia(item)`（有 `key` 且不是 `local`）。
少了这个判断，一张示例照片可能发出 `PUT /api/media/1`，静默改掉一张无关的真实照片。

相册上也有一份同样的标记：`album.mine`。访客看到的是公开相册，**不能编辑、不能改名**，
所以「编辑相册」按钮只在 `mine` 为真时出现。

## 相册 id 一律当字符串

`albumId`、`openAlbum`、`albumTotal` 的入参都是字符串。相册 id 会在 `<select>` 的
`value`、筛选键、接口参数之间来回走，类型一旦一边是数字一边是字符串，
`'12' === 12` 这种比较会让筛选**静默地少一批照片**——不报错，只是照片不见了。

## 相册名为什么在照片上还留一份

照片同时带 `albumId`（真归属）和 `albumName`（显示副本）。相册表对访客基本不可见
（只放行「装着公开照片」的那些，见 `supabase/schema.sql` 的 RLS），而公开照片墙要显示
相册名。所以**改动归属的地方两列必须一起写**：只写 `album_id` 会让照片挂着旧名字，
相册改名后也一样（`services/api.js` 的 PUT 会顺手更新副本）。

## 关闭动效是共用件

`GalleryViewer` 的退场和 `modules/modal/ReadingSheet.vue` 用的是同一份
`composables/useDustClose.js`（时长常量、量位置、量不到时的兜底、等粒子飞完再 `emit('close')`）。
粒子层是 `modules/modal/DustBurst.vue`。

改动效时**不要只改一边**：时长各写一份，症状就是「粒子还在飞，组件已经被摘掉了」，
而且只在自己那处看得见。全屏看图的 `AppShell` 外层也不要再包 `<Transition>`。
